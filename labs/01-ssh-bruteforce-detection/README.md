# SSH Brute Force Detection & Prevention (Linux / VirtualBox Lab)

## Overview

Built an end-to-end detection engineering lab in a local VirtualBox environment to simulate SSH brute-force activity and implement automated detection and mitigation using Linux authentication logs and Fail2Ban.

The lab captures authentication telemetry from a controlled Ubuntu Server VM, identifies repeated failed login attempts, and automatically blocks offending source IPs, modeling a simplified SOC-style detection and response workflow.

This project was built and tested as a local virtual machine lab, not a public cloud deployment.

---

## Key Results

- Generated controlled SSH brute-force activity against a local Ubuntu Server VM
- Identified repeated failed login attempts in `/var/log/auth.log`
- Triggered Fail2Ban detection thresholds based on observed attack patterns
- Verified automated IP banning using `fail2ban-client`
- Built Python-based log parsing and time-window detection logic for repeated SSH failures

---

**Infrastructure**

- Windows 11 host system
- Oracle VirtualBox
- Ubuntu Server 24.04 LTS guest VM
- Host-only networking

**Security Components**

- OpenSSH Server (`sshd`)
- Fail2Ban (automated IP banning)

**Log Source**

/var/log/auth.log

SSH authentication activity is generated by simulated attack behavior and analyzed to build detection logic.

All attack activity in this lab was generated in a controlled local environment from the host system against the guest VM.

## Detection Labs

### Lab 01 – SSH Authentication Logging

Understand how SSH authentication attempts are recorded in Linux authentication logs.

## Why This Project Matters

Detection engineering often begins with **raw system telemetry**, not security tools.

Understanding how attackers interact with systems and how those interactions appear in logs is essential for building effective detections.

This project demonstrates how detection logic can evolve from:

~~~text
manual log investigation
→ automated analysis
→ operational detection rules
~~~

This mirrors how real security teams develop and refine detection capabilities.
