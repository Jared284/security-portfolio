# SSH Brute Force Detection & Prevention (Linux / AWS)

## Overview

Built an end-to-end detection engineering lab to simulate real-world SSH brute force attacks and implement automated detection and mitigation using Linux authentication logs and Fail2Ban.

The system captures authentication telemetry, identifies repeated failed login attempts, and automatically blocks malicious IP addresses, modeling a simplified SOC detection and response workflow.

---

## Key Results

- Captured real SSH brute-force traffic against an exposed EC2 instance
- Identified repeated failed login attempts via /var/log/auth.log
- Triggered Fail2Ban detection thresholds based on attack patterns
- Automatically banned malicious IP: 128.6.147.18
- Verified active bans using fail2ban-client

---

**Infrastructure**

- AWS EC2 (cloud deployment)
- Ubuntu Server 22.04 / 24.04

**Security Components**

- OpenSSH Server (`sshd`)
- Fail2Ban (automated IP banning)

**Log Source**

/var/log/auth.log

SSH authentication activity is generated by simulated attack behavior and analyzed to build detection logic.

## Detection Labs

The detection section contains six labs demonstrating the evolution of detection logic.

### Lab 01 – SSH Authentication Logging

Understand how SSH authentication attempts are recorded in Linux authentication logs.

Focus:
- log structure
- successful vs failed login events

---

### Lab 02 – SSH Brute-Force Pattern Identification

Identify suspicious authentication patterns by aggregating repeated failed login attempts.

Focus:
- brute-force indicators

---

### Lab 03 – Fail2Ban Automated SSH Mitigation

Deploy Fail2Ban to automatically block IP addresses responsible for repeated authentication failures.

Focus:
- log-based detection

## Why This Project Matters

Detection engineering often begins with **raw system telemetry**, not security tools.

Understanding how attackers interact with systems and how those interactions appear in logs is essential for building effective detections.

This project demonstrates how detection logic can evolve from:

~~~text
manual log investigation
→ automated analysis
→ operational detection rules
~~~

This mirrors how real security teams develop and refine detection capabilities.
