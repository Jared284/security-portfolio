# Lab 04 – SSH Authentication Log Triage

## Objective

Investigate repeated SSH authentication failures to determine whether the observed activity represents benign user error or automated brute-force attack behavior.

---

## Data Sources

- `/var/log/auth.log`
- OpenSSH authentication events generated by `sshd`

---

## Initial Signal

Multiple SSH authentication failures were detected originating from a single source IP address within a short time window.

This activity triggered investigation to determine whether the behavior was legitimate user error or malicious probing.

---

## Investigation Process

Authentication logs were examined using standard Linux log analysis commands.

Commands used:

```bash
grep "Failed password" /var/log/auth.log
```

Filtering results by source IP revealed repeated authentication failures from the same host.

Example log entry:

```
Failed password for invalid user admin from 192.168.56.101 port 53712 ssh2
```

Multiple similar events appeared within a short time interval.

---

## Observations

The investigation revealed several characteristics consistent with automated brute-force behavior:

- Repeated failed authentication attempts from a single IP address
- Attempts targeting invalid or non-existent usernames
- High frequency of login attempts within a short time window
- No successful authentication events associated with the activity

Individual failed logins represent low-signal events, but aggregated activity across time and source IP revealed a clear attack pattern.

---

## Assessment

Based on the volume and frequency of failed authentication attempts, the activity is consistent with automated SSH brute-force probing rather than legitimate user error.

This type of activity is commonly observed on internet-exposed SSH services.

---

## Response and Outcome

The offending IP address exceeded the configured authentication failure threshold.

Fail2Ban automatically enforced a ban against the source IP.

As a result:

- The source IP was added to the SSH jail ban list
- Firewall rules were updated to block additional connections
- Subsequent SSH authentication attempts from the source IP were denied

This confirmed that detection signals successfully triggered automated mitigation.

---

## Analyst Takeaways

- Authentication logs provide critical visibility into SSH access attempts
- Raw logs are noisy; aggregation across time and source IP reveals attacker intent
- Repeated authentication failures are a strong indicator of brute-force activity
- Automated defenses such as Fail2Ban can effectively mitigate repeated attack attempts once detection thresholds are exceeded
